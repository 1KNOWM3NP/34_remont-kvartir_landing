# TASK_BRIEF — слепок задачи (для исполнения любой моделью с нуля)

## Исходный запрос владельца (суть диалога)
Сделать лендинг для компании по ремонту квартир. Владелец не задаёт структуру и стек — выбирает исполнитель, но с условиями: современно («не дедовский сайт»), красивый трендовый дизайн (полная свобода), интересная типографика, иконки. Обязательные элементы: всплывающее окно (модалка) с формой заявки, калькулятор стоимости, блок работ для клиентов (портфолио), блок с видео о компании, красивый hero-блок. Оплаты на сайте нет — только воронка: с первого до последнего блока вести посетителя так, чтобы ему было интересно и он захотел оставить заявку.

## Функциональные требования
1. **Hero**: оффер («ремонт под ключ за N дней»), подзаголовок-выгода, 2 CTA (калькулятор / бесплатный замер).
2. **Калькулятор**: площадь (слайдер) + тип ремонта (косметический/капитальный/евро) + количество комнат + опции (сантехника, электрика, дизайн-проект) → диапазон цены + CTA «Получить точную смету».
3. **Модалка заявки**: открывается по всем CTA, поля имя + телефон, валидация, маска телефона, экран успеха.
4. **Портфолио**: карточки «до/после», метраж, срок, цена.
5. **Видео**: блок о компании (эмбед, постер-заглушка).
6. **Дополнительно**: соцдоказательство (цифры/отзывы), блок «боли», преимущества, «как работаем» (4 шага), FAQ, финальный CTA с формой.
7. Заявки: слой-абстракция `src/lib/api.ts` (сейчас localStorage + заглушка, позже SQLite-бэкенд).

## Технические решения (приняты, можно менять обоснованно)
- Стек: Vite + React + TypeScript + Tailwind CSS v4. Причина: скорость, компоненты под калькулятор/модалку, лёгкий dev-сервер для визуальной проверки.
- Репозиторий: `34_remont-kvartir_landing` на GitHub, коммиты мелкие и частые, пуш после каждого шага.
- Визуальный контроль: Playwright MCP (основной) + Chrome DevTools MCP (запасной); проверять десктоп и 375px, клики по модалке и калькулятору.
- Дизайн: трендовый, тёплая «домашняя» палитра, крупная дисплейная типографика, SVG-иконки, тач-зоны 44px, контраст 4.5:1, mobile-first.
- Копирайтинг: русский язык, конкретика, один оффер на секцию, сильные CTA («Получить смету», а не «Отправить»).
- Процесс: один чат = одна задача из ROADMAP.md; порог ротации чата — ~20% остатка контекста; в конце чата — коммит, пуш, хэндовер (что сделано, hash, следующая задача).
